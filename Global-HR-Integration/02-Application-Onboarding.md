# Application Onboarding & Configuration

## 1. Step-by-Step UI Configuration
To ingest the flat-file HR data, the application was configured in SailPoint IdentityIQ using the out-of-the-box `DelimitedFileConnector`. Below are the exact UI steps taken to establish the authoritative source:

1. **Initialize the Application:** Navigate to **Applications > Application Definition** and click **Add New Application**.
2. **Define Base Properties (Details Tab):**
   * **Name:** `Global HR System`
   * **Application Type:** `DelimitedFile`
   * **Authoritative Application:** Checked (This critical flag instructs IdentityIQ to use this feed to birth and govern Identity Cubes, rather than treating it as a downstream target).
3. **Establish Transport & Parsing (Configuration > Settings Tab):**
   * **File Path:** `VARIES FROM SYSTEM TO SYSTEM`
   * **Parsing Type:** `Delimited`
   * **Delimiter:** `,` (Comma)
   * **File Has Column Headers:** Checked

4. Click **Save** to lock in the baseline connector settings.

## 2. Schema Discovery
After saving the connection settings, the schema was discovered directly from the CSV header row. 

1. Navigate to the **Schema** tab and click **Discover Schema**. IdentityIQ successfully parsed all 10 column headers.
2. To ensure IdentityIQ can uniquely identify every incoming record, the `employeeId` column was explicitly promoted to act as the **Identity Attribute**. 
3. All other attributes (`firstName`, `lastName`, `email`, `department`, `jobTitle`, `managerId`, `location`, `costCenter`, `status`) were ingested as standard string types. 
4. *Note:* Entitlement scopes and change detection attributes were intentionally left disabled at this layer, as role-based access will be calculated dynamically by IdentityIQ's core engine, not the HR connector itself.
